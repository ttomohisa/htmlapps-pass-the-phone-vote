# Pass-the-Phone Vote v1.0.4 / スマホ回し投票 v1.0.4

## 日本語

スマホでの設定・投票・開票結果の操作を見直しました。票の扱いと秘密投票の仕組みは変更していません。

### 変更点

- スマホの設定画面から重複する案内や装飾を減らし、質問と選択肢を入力しやすくしました。
- 次の人への受け渡し後、スマホでは「次の人が投票する」から1回で新しい投票画面へ進めます。
- 投票完了のチェックマークと、好評だった1.2秒の「長押しして開票」を維持しました。長押しが難しい場合の確認付き開票も使えます。
- 投票画面の「秘密投票」ラベルをスマホで非表示にし、確認文を短くしました。
- 結果画面の「結果を残す」にコピー・共有・テキストファイル保存をまとめ、「続けて投票する」と分けました。
- 同じ条件で再投票する操作と、設定を編集して新しい投票を作る操作の違いを明記しました。
- スマホでは「完全ローカル処理」バッジとフッターなど、重複した表示を省きました。プライバシーの説明はヘルプに残しています。

### 動作・制限

- 投票ごとの個別回答履歴は保存しません。確定時には選択肢別の合計票数だけを更新します。
- 投票途中の復元はブラウザの `sessionStorage` に保存できた範囲に限ります。未確定の回答は保存しません。
- 投票を中止・再投票・新規作成する操作には、既存の確認を残しています。
- `.txt` 保存、コピー、端末の共有機能は集計結果のみを対象にします。共有先への送信は利用者が選択します。
- 実行時に外部CDNやアプリ用APIへの通信は行いません。最初のHTMLの取得には通信が必要です。

### 配布ファイル

- `index.html`: 読みやすい単一HTML版
- `index.self-extract.html`: 自己展開型の単一HTML版

## English

Refined the mobile setup, voting, and result screens without changing the aggregate-only vote model or the private handoff safeguards.

### Changes

- Simplified the mobile setup and ballot layouts by removing repeated explanations and unnecessary decoration.
- On phones, each next participant opens a fresh ballot directly from the neutral handoff screen with one tap.
- Kept the original completed-vote checkmark and 1.2-second **Hold to reveal** gesture, plus its confirmation-based alternative.
- Removed the redundant **Secret vote** label from the mobile ballot and shortened the vote-confirmation note.
- Grouped Copy, Share and text-file download under **Keep the results**, separately from the options to vote again or create a new vote.
- Clarified the difference between repeating with the current setup and editing the setup for a new vote.
- Removed redundant mobile chrome, including the local-processing badge, while keeping privacy information in Help.

### Behavior and limits

- Individual voter-to-choice records are not stored; a confirmed vote only increases its option's aggregate count.
- Reload recovery uses `sessionStorage` when available and does not store unconfirmed choices.
- Stop, repeat, and new-vote operations retain their existing confirmation safeguards.
- Copy, Share, and `.txt` downloads contain aggregate results only. The destination of a share is chosen by the user.
- No runtime CDN or application API traffic is required after the initial HTML is loaded.

### Downloads

- `index.html`: readable standalone HTML
- `index.self-extract.html`: self-extracting standalone HTML

## Release checklist

1. Merge PR #10 into `main` after review (manual merge by repository owner).
2. Confirm **Deploy standalone app to GitHub Pages** succeeded for the merge commit. Its `standalone-html-<sha>` artifact contains the generated release variants.
3. Download the `dist/index.html` and `dist/index.self-extract.html` files from that artifact. Do not assume the GitHub repository contains the ignored `dist/` build output.
4. Create an annotated tag `v1.0.4` on the reviewed merge commit and push it.
5. Create the GitHub Release for `v1.0.4`, copy the relevant notes above, and attach both standalone HTML files.
6. Open both attached HTML variants, including an offline check, and verify the public Pages app is the expected v1.0.4 build.

**Important:** Tag creation does not trigger a release-artifact build automatically in the current workflows. GitHub Pages is deployed on pushes to `main`. Use the successful `main` build artifact when attaching Release downloads.
